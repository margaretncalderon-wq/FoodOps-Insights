**Key Technical Concepts**
-   **Membership-Aware Access Control:** The application's core architectural pattern for collaboration. Endpoints must not rely on a user's single . Instead, they must query the  collection to get a list of all s the user has access to and include them in database queries (e.g., using MongoDB's  operator). This was extended to the Execution Hub in this session.
-   **Proactive Data Repair:** The  function is a runtime mechanism that detects and fixes a specific data inconsistency (a company owner missing their own membership record). This prevents a cascade of bugs related to visibility and permissions for new users.
-   **Component-Driven Development:** A single  component was built, enhanced based on feedback, and successfully reused across two different major modules (, ), demonstrating effective and maintainable frontend architecture.
-   **Isolated File Handling:** A dedicated backend flow was created for Execution Hub attachments, including a specific upload endpoint, a separate storage directory (), and a corresponding static file-serving route. This keeps it separate from other upload types.
